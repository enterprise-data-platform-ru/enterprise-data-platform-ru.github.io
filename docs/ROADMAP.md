# Поэтапные задачи для Coding Agent

Выполнять по одной. Сначала передать Qwen Code `QWEN.md`, затем отдельную задачу.

## 01 — Проверка стартового проекта (P0)

Установи зависимости (`npm install`), сохрани lockfile, выполни тесты и сборку. Исправь только блокирующие ошибки. Проверь `out/` на 360, 768, 1440 px, навигацию и FAQ. Не меняй визуальную концепцию. Критерий: тесты и сборка успешны, нет горизонтального скролла и битых ссылок.

## 02 — Контент и позиционирование (P0)

Изучи `src/content/site.mjs`, `Hero.jsx`, `Solutions.jsx`. Предложи 2–3 варианта позиционирования: архитектурный проект, интегратор или продукт. После выбора владельца измени только тексты. Критерий: нет неподтверждённых коммерческих обещаний, текст понятен CTO/CDO.

## 03 — Декомпозиция секций (P1)

Раздели `Solutions.jsx` на самостоятельные компоненты, не меняя внешний вид. При необходимости вынеси стили каждой секции в CSS modules. Критерий: визуальное поведение сохранено, `npm test` и `npm run build` проходят; обнови тесты путей.

## 04 — Документация (P1)

Предложи структуру `/docs/` для архитектуры, компонентов, безопасности и эксплуатации. Начни с одной статической страницы Next.js. Nextra рассмотри отдельно: проверь совместимость с установленной версией Next и статическим экспортом. Критерий: рабочий URL, навигация, SEO, без поломки лендинга.

## 05 — Интерактивная архитектура (P1)

Добавь переключение сценария Lakehouse/CDC/BI/AI для логической схемы. Используй минимальный client component, доступные кнопки и клавиатуру; данные — в `site.mjs`. Критерий: сценарии корректно меняют схему, SSR/static export не нарушен.

## 06 — Контакты (P1, после решения владельца)

Согласуй действующий email и необходимость формы. Если требуется форма — отдельно спроектируй серверный endpoint, валидацию, rate limit, защиту от спама и правила хранения данных. Не симулируй успешную отправку. Критерий: реальная доставка, отсутствие секретов на клиенте, понятные ошибки и необходимые согласия.

## 07 — Production (P1)

Проверь workflow GitHub Pages, `npm run check:export`, корневой домен и временный project URL с `NEXT_PUBLIC_BASE_PATH`, DNS/TLS, robots и sitemap. Инструкция в `docs/GITHUB-PAGES.md`. Зафиксируй lockfile и процесс rollback. Критерий: воспроизводимая сборка, успешная публикация из main и HTTPS. Docker/Nginx — альтернативный вариант. Не меняй DNS и не выполняй push без разрешения.

## 08 — Расширение сайта (P2)

Отдельные страницы компонентов, архитектурные статьи, отраслевые решения и кейсы. Используй только реальные подтверждённые сведения. Разбивай каждую страницу на отдельное задание.
